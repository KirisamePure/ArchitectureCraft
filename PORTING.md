## Validation evidence

Validated with `./gradlew build runClientGameTest` on Java 21, Minecraft 1.21.10 and software OpenGL: 225 JUnit cases, 28 mod server GameTests plus the Fabric baseline, and the client suite passed.

- `ReferenceParityTest`: metadata for all 106 entries, exact page ordering, all 24 reference mounting matrices, collision masks/support, window compatibility and diagonal/glass flags.
- `ArchitectureGameTests`: 28 mod tests covering unpaid and paid output, vanilla inventory extraction paths, selection memory, persistence, multiple menus, automation, placement, collisions/support, mining, separate drops, tools, glazing, glow and native material tags. The server also runs Fabric's baseline test.
- `ArchitectureClientTest`: loads all catalog item models, checks material UVs and emissive tags, renders the catalog, clicks category/shape buttons and extracts output, then compares a networked placement with its rendered preview. Checks contextual window frame outlines and captures the restored UI and placement screenshots.

These checks exercise representative gameplay paths and reference data; they do not exhaust every material, world arrangement or resource pack. The original UI screenshot was compared with the actual 1.21.10 client capture. The port uses modern Minecraft's rendering, lighting, inventory and data-pack APIs, so pixel-identical world lighting is not expected.

Intentional changes: unpaid sawbench previews cannot be duplicated by breaking the bench; paid remainders are returned. Material acceptance and emissive overrides use native block tags in place of legacy configuration entries. Optional mod integrations and conversion of old world formats are outside this port's scope.

The material-acceptance regression also registers a transparent full cube in the test mod with no glass superclass and no acceptance tag. It verifies actual sawbench output, source material and extraction costs, alongside vanilla transparent cubes/slabs and rejection of containers and non-full shapes. Production acceptance uses the input item’s block-state component and full collision shape; opacity and vanilla glass classes are not requirements.

Transparent-surface rendering follows the source model's directional shading and ambient-occlusion flags with neutral shape occlusion brightness, as in the original implementation. Boundary triangles fully covered by compatible neighboring rendered faces are removed according to the source block's `skipRendering` rule. Collision bounds are not used to infer face coverage. Client regressions cover matching glass slabs, a vanilla glass neighbor, a frame with holes, a different opaque material, and a custom unshaded/no-AO source model. Shape-to-shape removal conservatively retains partially covered triangles. Native material faces touching shapes are clipped to their uncovered polygons, including partial contacts. Intersections away from cell boundaries are retained; this is shared-boundary handling, not a general constructive-solid-geometry union.

Slope smooth-lighting correction: oblique/curved triangles explicitly disable cube-corner AO through FRAPI, while retaining directional shading and block/sky light. Axis-aligned faces still honor source-model AO. Shape blocks return neutral AO occlusion brightness rather than inheriting the full material cube's darkening factor. Client regression checks the emitted flags for roofs, several slopes and a sphere with smooth lighting enabled, and captures a stone-brick slope wall by day and night. No Sodium APIs or dependencies are introduced. Direct Sodium validation was blocked by the environment proxy (HTTP CONNECT 403 for Modrinth/GitHub/CaffeineMC downloads), even after network access was granted; Indigo validation does not establish Sodium visual parity.

Native/shape seam correction: the prior check only tested the shape's side of a native-block contact. A Fabric model wrapper now handles the native material's side for materials whose own `skipRendering` rule hides matching faces. It subtracts the neighboring shape's actual boundary triangles and triangulates the visible remainder while interpolating original UVs, colors, light values and normals. Non-contact models forward to their original renderer; no mixins, mod IDs or optional dependencies are involved. Geometry is recomputed from the current neighbor state rather than cached by native block state. The real client regression exercises 13 native-output cases: full coverage in all six directions, bottom/top slabs, a roof slope, window-frame holes, different materials/colors and an absent neighbor. It verifies visible areas, preservation of other faces, UV bounds and native culling/emissive flags. Build, existing server tests and the complete Indigo client suite passed. The supplied third-party material and Sodium have not been directly tested.

Placement preview pipeline correction: preview geometry is submitted through the standard custom-geometry command queue at `BEFORE_ENTITIES`, so the active entity renderer manages the shader, render target and buffer flush. It no longer appends entity vertices to the shared buffer after entity drawing, and extraction no longer depends on the block-outline render flag. F1, open screens and spectator mode suppress the preview. Regression captures the same camera with and without the preview, asserts changed pixels in the world target region (excluding the hand/UI), checks stale-state removal and F1 restoration, and compares the planned geometry with networked placement. Build/server and Indigo client validation passed. User-reported target: Iris 1.9.7 with E-LITE. Direct Iris/shader validation remains blocked by the download proxy's HTTP CONNECT 403; these tests do not establish compatibility with that exact combination. No Iris dependency or version-specific hooks are added.

Double Roof Tile material-interface correction: the original asset contains only the external cube shell. Two opposite diagonal caps now close the complementary material prisms along local y=x. Rendering hides a cap when the neighboring half is the same/connected material or an opaque solid surface; an opaque half beside glass retains its own textured cap. Material selection uses normal block render layers and face-hiding rules rather than glass IDs. World models, placement previews and items share the repaired geometry; item triangles are grouped by material before baking so hidden caps cannot shift render-layer assignment. Unit checks verify closed edges and half-block volume for both prisms under all 24 rotations. The client checks six material combinations in all 24 orientations, verifies opaque item layers, and captures glass/stone screenshots in both orders. Collision, saved data and material costs are unchanged. Existing placed blocks use the new geometry after updating the mod.
